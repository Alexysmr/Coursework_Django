## Курсовая работа. Создание веб-приложения на Django, позволяющее пользователям управлять рассылками сообщений для клиентов в рамках обучения по специальности "Разработчик Python" университета Skypro.  

**Задачи выполняемые программой:**  
Создание, просмотр, редактирование и удаления рассылок, а также отправка сообщений по требованию.  

**Для пользователей:**  
Запуск сервера: в корневом каталоге проекта в командной строке ввести команду `python manage.py runserver`, в браузере открыть страницу http://127.0.0.1:8000  

## Для разработчиков:

**Состав программы:**  
- manage.py - точка входа;  
- requirements.txt - файл списка зависимостей и версий;  
- mailing_project/ - директория проекта;  
- приложения и вспомогательные модули:  
	- clients - создание записей о клиентах;  
	- contacts - контакты;  
	- mailing - рассылки;  
	- users - регистрация пользователей сервиса
	- fixtures/ - директория расположения фикстур;  
	- auxiliary/ - директория вспомогательных модулей constants.py, services.py, mixins.py, scheduler.py;  

Требуемые версии и зависимости:  
 - в соответствии с requirments.txt.  

Установка:  
 - установить стек : Python, Django, PostgreSQL, Redis, django-apscheduler, WhiteNoise, Bootstrap;  
 - в PostgreSQL, создать пользователя с правами владельца базы данных.  
Предупреждение:  
 ❌ Не давайте пользователю SUPERUSER (это администратор всей СУБД);  
 ❌ Не используйте пользователя postgres (суперпользователь по умолчанию) для Django;  
 ❌ Не храните пароль в коде (используйте .env);   
 - клонировать проект , создать .env в соответствии с шаблоном, выполнить pip install -r requirements.txt, выполнить миграции migrate.
 
**Учётные записи для проверки загружамые из фикстуры:**
Для упрощения создания базового необходимого количества пользователей после выполнения migrate можно загрузить фикстуру:
python manage.py loaddata fixtures/groups_and_users.json
Данные учётных записей размещены в открытом доступе только с целью проведения проверки работоспосбности данного проекта

Роли пользователей сервиса:  
 - "Пользователь" - регистрируется на сайте через подтверждение своей почты. "Время жизни" высылаемого на указанную почту токена 
 подтверждения задается в auxiliary/constants.py. Возможности: создание, просмотр, редактирование и удаление своих клиентов и рассылок, 
 просмотр статистики по своим рассылкам;  
 - "Менеджер" - создается только администратором сайта. Возможности: создание, просмотр, редактирование и удаление своих клиентов и 
 рассылок, просмотр всех клиентов и рассылок, просмотр списка пользователей сервиса, блокировка пользователей сервиса, отключение рассылок пользователей.  
 - "Администратор"(он же суперпользователь, он же Бог и царь в этой системе) - существует изначально, не может только заблокировать себя.

**Команды отправки сообщений по требованию:  
 - отправка рассылок по требованию выполняется в режиме администратора, т.е. любую рассылку можно отправить, при этом статус рассылки не меняется;
 - python manage.py send_mailing - выводит список всех рассылок. Информация о рассылках выводится по колонкам pk, title, status, stopped_by, last_attempt;
 - python manage.py send_mailing --pk N  - отправка рассылки под № N, номер рассылки нужно выбрать из выведенного списка.  

**Особенности запуска**:
 - Для проверки работы проекта режим разработки DEBUG=False;
 - ALLOWED_HOSTS = ['*']  - временно для проверки, в прадакшене меняется на конкретные хосты.  
 - **Важно:** После выполнения миграций выполнить python manage.py collectstatic --noinput (собрать **статику** в staticfiles/ с хешами);
 - запуск - python manage.py runserver;  

**Кэширование:**
- Серверное (Redis): счётчики на главной для менеджера (TTL 300 сек), инвалидация через сигналы и явно в сервисах;  
- Клиентское: WhiteNoise + ManifestStaticFilesStorage (хеши в именах файлов, Cache-Control).

**Особенности работы с почтой:**
- Отправка писем настроена через SMTP-сервер mail.ru (smtp.mail.ru, порт 465, SSL).
- Параметры подключения (EMAIL_HOST, EMAIL_PORT, EMAIL_USE_SSL, EMAIL_HOST_USER, EMAIL_HOST_PASSWORD) задаются в .env.
- Для проверки использовался реальный почтовый ящик mail.ru; в .env.example указан шаблон.
- Отправка сообщений на странице "Контакты" производится в консоль.
